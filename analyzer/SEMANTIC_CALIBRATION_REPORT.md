# MyMusic Semantic v2 最終特徴量評価

- 評価日: 2026-08-29
- 結論: **calibrationを追加せず、raw headをSemantic v2としてFIXする**
- 音源再読込: 0
- 作品名・Artist・Title・Folderの利用: この報告の評価用groupingのみ

## 1. 現在の特徴量仕様

Semantic v2は、検証済みのDiscogs EffNet backboneから保存済み1280次元Embeddingを生成し、次のheadを適用する。

| 特徴量 | 出力元 | 集約 |
|---|---|---|
| vocal / instrumental | `voice_instrumental-discogs-effnet-1` | patch確率の算術平均 |
| aggressive | `mood_aggressive-discogs-effnet-1` | patch確率の算術平均 |
| calm | `mood_relaxed-discogs-effnet-1` | patch確率の算術平均 |
| piano / electronic / ambient | 汎用tags head | patch確率の算術平均 |
| dark | 汎用mood head | patch確率の算術平均 |
| drumAndBass | Discogs backboneの該当class | patch確率の算術平均 |

既知誤判定やTemple of Timeは全3区間で高く、一部patchだけが平均を押し上げた問題ではない。Taswellのように区間差が大きい曲もある。したがってmedian化やmax除去だけでは前者を直せず、後者の曲構造を失う。

原因の優先度は次のように判断する。

1. **voice/instrumental headのgame/OST音色への局所的なdomain shift**: 一貫して高いinstrumental曲候補が存在するため最有力。
2. **実際の声・コーラス・ハミングを含む曲**: `Goron Humming`や歌唱を含むOSTなどが高値群へ混ざり、正解ラベルなしではhead誤差と分離できない。
3. **aggregation**: 区間差の大きい曲には影響するが、全区間で高い誤認を説明しない。
4. **frontend不整合**: checksum済みの同一frontendとEmbeddingを使用し、patch平均がexportと一致するため、現時点で不具合の証拠はない。

## 8. 各特徴量の問題

- `vocal/instrumental`: 大規模には機能しているが、声に似た音色や特定のgame/OST曲を曲全体でVocalと誤認する残存例がある。
- `aggressive/calm`: 強い逆相関はあるが補数ではない。インスト全体の標準偏差は0.180/0.234で、戦闘語群と静穏語群も期待方向に分かれる。
- `ambient`: Minecraft平均0.328、Zelda 0.146、Pokémon原曲0.090で、実用的な群差と分散がある。
- `piano/electronic`: group間差と曲内順位があり、calm/ambientの別名にはなっていない。
- `dark`: 全体p99が0.181と値域は低め。ただしZelda戦闘／静穏で効果量0.757があり、順位情報は機能している。見た目の値域だけを広げる補正はしない。
- `drumAndBass`: OST群では中央値0.0028と疎だが、専用genre classとして自然。均等化しない。
- `energy/tempo`: 新規ライブ曲にはproduction DSP baselineがないため未出力。必要ならSemantic calibrationとは別に、通常DSP Analyzerの安全な差分更新を設計する必要がある。
- 2.048秒未満の16曲: model patchを構成できず未出力。paddingで意味を変える修正は今回行わない。

## 9. 補正の必要性

**補正しない。** 理由は以下。

- 既存ボーカル中心3,552曲の95.3%が`vocal > 0.5`、インスト密度の高い主要4群では0〜6.6%で、大規模な分離は既に成立している。
- インスト内部でもambient、calm、aggressive、piano、electronicに十分な分散とgroup差がある。
- 高vocalのOSTには実際の歌唱、コーラス、ハミングが混在し、教師ラベルなしではcalibration targetを定義できない。
- global logit shiftやtemperature scalingは既存ボーカルのscoreも動かす。改善量と回帰量を測れる正解ラベルがない状態では過学習になる。
- aggregation変更は曲全体で一貫した誤認を修正できず、区間差という有用な情報を変える。
- dark等の値域を見栄えのためにmin-max正規化する根拠はない。

将来再検討する条件は、作品横断で層化した人手ラベル付きセットを作り、raw headに対してVocal/Instrumentalのprecision/recallとcalibration errorを測定できた場合に限定する。

## 11. 残存する既知の限界

1. 作品groupingは評価用proxyで、各曲のVocal/Instrumental正解ラベルではない。
2. `対戦！バトルアリーナ`、Temple of Time等、明らかなinstrumental候補を高Vocalとする局所的誤認は残る。
3. 声、コーラス、ハミング、声に似たシンセや管弦音色の区別はbinary headだけでは不安定になり得る。
4. 3区間×最大30秒のsamplingで曲全体を完全には観測しない。
5. 2.048秒未満は分析できない。極端に短い曲では1 patchだけのscoreになる。
6. 新規ライブ曲の`energy/tempo`はSemantic単独では生成しない。
7. generic tags/moodの絶対値は相互に校正された確率ではなく、特徴量ごとの順位・相対差として扱う。

## 12. Semantic v2をFIXしてよいか

**FIXしてよい。** 現在のraw head、mapping、patch mean aggregation、checksum済みモデルをSemantic v2の確定仕様とする。Artist、Title、Album、Folder、ゲーム名による補正、全体rescale、min-max正規化は追加しない。

今後は数曲の例外で再調整せず、次のどちらかが起きた場合だけversionを上げて再評価する。

- 作品横断の人手ラベル付き評価セットで重大なsystematic biasが再現した。
- backbone/head/frontend/aggregationを意図的に変更する製品要件が生じた。

このFIX判断はSemantic headに対するもので、ライブライブラリの差分走査、Embedding cache、production DSP Analyzerの境界は維持する。
