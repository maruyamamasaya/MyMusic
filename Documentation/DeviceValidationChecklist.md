# 次に実機テストするときのチェックリスト

更新: 2026-10-08。

## 方針と使い方

個人の日常利用で使えているため、大規模ライブラリの定量計測を今すぐ行う必要はない。未計測は性能不良を意味しない。起動・検索の遅さ、再生の途切れ、発熱・電池消費など具体的な困りごとが出た場合、または配布範囲を広げる前に、必要な項目を選んで確認する。

「次に何をテストすればよいか」「実機確認で残っていること」を聞かれたら、この文書を最初に参照する。毎回全項目を実施する義務はない。選んだ項目と未実施項目をsessionへ記録し、この原本のチェック欄を過去の成功だけで埋めない。

ハイレゾ専用再生は、EQ・音量補正・フェード等の加工を加えず素の音を聴く経路として分離する。検証の目的は通常再生との機能統一ではなく、操作性・切り替えの安定性・実出力の確認。rate一致だけでbit-perfectとは判断しない。

## 開始前

- [ ] 今回の目的と対象項目を決める（日常利用の確認／症状の再現／配布前）。
- [ ] アプリrevision、Debug／Release、端末とOS、曲数、接続先、音源のcodec・rate・bit depthを記録する。
- [ ] データ変更・復元を試す場合は、事前に外部backupを確保し、試験用データで行う。
- [ ] 実機deployやSimulator testを行う場合はAGENTS.mdの手順に従う。deployは明示依頼時のみ。Simulatorは既存1台・並列OFF、XCTestDevicesの開始前後を記録する。

## 普段の再生と操作

- [ ] 通常曲で再生／一時停止／再開、シーク、曲送り・曲戻し、自然終了後の次曲を確認する。
- [ ] ホーム・検索・ライブラリ・Playlistから再生し、曲順と現在曲表示が意図どおりか確認する。
- [ ] 曲を替えたときや別画面へ移ったときに、二重再生、意図しない停止、遅れて始まる古い要求がないか確認する。
- [ ] 好きな曲・評価・Playlist編集など、今回の変更に関係する既存操作を確認する。

## Background・ロック画面・AirPods（対象機器がある場合）

- [ ] 通常再生中に画面ロック／別アプリへ移動し、再生継続と復帰後の状態表示を確認する。
- [ ] ロック画面・AirPodsから再生／一時停止／曲送りを操作し、曲名・進捗・実際の音が一致するか確認する。
- [ ] AirPodsの接続／切断、別出力への変更、通話等の割り込み後の挙動を確認する。意図しない自動再開がないか記録する。
- [ ] ハイレゾ経路でもbackground／ロック時の現挙動を記録する。未対応の操作は未対応として扱い、音への加工機能追加を完了条件にしない。

## ハイレゾ・USB DAC・経路切り替え

- [ ] 各タブのmini playerから専用再生画面へ戻れるか、再生／一時停止／シーク／曲送りが使いやすいか確認する。
- [ ] 通常再生 → ハイレゾ、ハイレゾ → 通常再生を確認し、二重再生、無音、古い曲の再開がないか確認する。
- [ ] rate準備中の停止・連続選曲・通常再生への切り替え・Files診断画面を閉じた後の通常再生を確認する。
- [ ] USB DACの初回接続、再接続、rateの上下切り替えと実曲再生を確認する。詳細は[Hi-Res rate切替手順](HiResRateSwitchVerification.md)に従う。
- [ ] 音源rate、Session実rate、Audio Queue実rate、DAC表示を比較する。不一致や取得失敗を記録する。
- [ ] EQ・音量補正等を適用しない専用経路であることがUIから分かるか確認する。

## Watch（対象機器がある場合）

- [ ] 曲名・進捗・Artwork・お気に入り／評価がiPhoneと一致するか確認する。
- [ ] 再生／一時停止／曲送り・音量・通常／お気に入り／未発見shuffleを確認する。
- [ ] 通信できない状態から復帰し、現在状態と画像が再同期されるか確認する。失敗した操作が遅れて再生を開始しないか確認する。

## 性能計測（必要になった場合だけ）

人工的に曲数を増やす必要はない。まず普段のライブラリで確認し、1万〜2万曲はその規模のデータが利用可能な場合に対象とする。

- [ ] 起動からライブラリ操作可能になるまで、Home表示、検索入力から結果表示、ジャンル切り替えの時間を記録する。
- [ ] 同じ端末・データ・接続条件で比較する。cache復元と同期、初回起動と再起動を区別する。
- [ ] 引っかかりがある操作をInstrumentsで確認し、CPU、memory／allocation、frame hitchを記録する。
- [ ] 普段の連続再生時間と出力先で、途切れ・発熱・電池消費を確認する。時間・画面ON／OFF・充電状態を記録する。
- [ ] 数値だけで合否を決めず、利用時の支障と変更前との差を整理する。根拠のない一律閾値は設けない。

## 履歴・保全（関連変更の検証時）

- [ ] 自然終了／次へ／停止／一時停止を含め、履歴が二重記録されず実聴時間と終了理由が妥当か確認する。
- [ ] 再起動後にも履歴・Preference・Playlistが維持されるか確認する。
- [ ] 実データmigrationは正本を直接変更せずcopyで検証し、read-backとbackupを確認する。
- [ ] 外部Backup／Restoreは試験用データで、復元準備・次回起動・音楽フォルダ権限再取得・曲参照の再接続まで確認する。原本保管のbackup包含など未実装範囲は別途記録する。

## 結果の記録

sessions/YYYY-MM-DD-<topic>.mdへ、対象revision／端末／条件、実施項目、結果、再現手順、未実施・未対応・不明点を残す。実機deploy成功、Simulator test成功、実音源での操作確認、定量計測は分けて書く。現在の未検証範囲が変わった場合だけCURRENT.mdを更新する。
