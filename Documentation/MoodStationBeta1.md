# 気分ステーション Beta 1

## 目的と操作

「ホーム → プレイリストの直下」または「プレイリスト → ステーション」にある
「気分を伝えて再生」から、現在の気分に近い曲だけで一時的な再生キューを作る。

1. 「今、どんな音楽がほしい？」に回答する。
2. 「今日はどんな音の感じがいい？」に回答する。
3. 回答に近い候補曲に、区別できる特徴量が十分あれば最後の質問に回答する。
4. 選ばれた曲を確認して「このステーションを再生」を押す。

最後の質問は回答内容に合わせて、次の対応済み軸から選ぶ。

- 歌を聴きたい ↔ 音そのものを楽しみたい: vocal / instrumental
- 生っぽい ↔ 電子的: electronicの低さ / 高さを**音色の目安**として使う
- 穏やか ↔ 激しい: calm / aggressive

候補が区別できない場合と「特に決めずに任せたい」では2問で選曲する。
ユーザーは3問目を「どちらでも」として省略できる。

## 選曲とアーキテクチャ

`StationQuestionView → StationStore → MoodStationService → TrackFeature` と責務を分離する。
Viewは回答イベントと表示だけ、Storeは質問状態・Library/Feature/Historyとの接続・PlayerStoreへの再生要求、
Serviceは回答から特徴量ターゲットを作る純粋な選曲を担当する。AVFoundationへ直接触れない。

- 有効な特徴量がターゲット重みの50%以上ある曲だけを評価する。
- 欠損値は0や反対傾向として扱わず「不明」とする。NaN、無限、0...1外も使わない。
- 類似度0.6以上を候補にし、最大25曲にする。曲数を埋めるために無関係な曲は入れない。
- 近いスコアには小さいランダム幅を加え、同じ回答でも少し変化させる。
- 同じアーティストの連続と過度な集中を弱く抑制する。
- 通常シャッフル対象外の作業用・一時除外・永久除外曲は使わない。
- 再生直前にLibrary、特徴量、除外状態をTrack.IDで再確認する。
- 再生時は既存の`PlayerStore.playQueue`へ渡し、現在のキューを置き換える。

## 一時保存

生成結果は`StationStore`のメモリだけに保持し、通常／作業用プレイリストの永続化データを変更しない。
新しい回答を始めても、生成成功までは直前のステーションを残す。アプリ終了時には消える。

## 既知の制限

- 特徴量JSONを登録済みの曲だけが対象。端末内で解析しない。
- 「生っぽい」はacoustic専用分類ではなく、electronicの低さによる近似である。
- 複雑さ、展開量、なじみやすさ、年代感の信頼できる特徴量が現行schemaにないため、該当質問はまだ出さない。
- 選曲説明、好みの学習、ステーション履歴、通常プレイリストへの保存、曲単位の入替は未実装。
- Betaの分類スコアは正解率や確率ではない。
- 実機の音響再生、Background、Lock Screen、Control Center、AirPodsは今回未検証。

## 検証項目

- 気分／音の回答による順位差、分岐と2問終了、3問目省略
- 欠損・不正値・特徴量不足、空候補、最大曲数、重複排除、アーティスト分散
- Storeの質問遷移、生成、再生キュー接続、永続プレイリスト非変更
- 再生直前の除外曲再確認、特徴量なしの案内状態
- SimulatorでLight/Dark Mode、Dynamic Type、質問分岐、結果一覧、実再生操作を目視確認する
